# 하네스 파이프라인

이 문서는 Codex 하네스의 작업 단계를 3~5단계 안에서 정의하고, 각 단계의 출력 파일과 실패 시 복귀 지점을 정리한다.

## R3 파이프라인 요약

| 순서 | 단계 | 설명 |
| --- | --- | --- |
| 1 | 입력 확인 | `input/PRD.md`와 필요한 컨텍스트 문서가 있는지 확인한다. |
| 2 | 스토리 생성·확인 | `input/PRD.md`에서 `output/story-service.md`를 생성하고 사용자 확인을 받는다. |
| 3 | 디자인 기준 확인 | `context/design.md`의 기본값과 게이트 조건을 확인한다. |
| 4 | `AGENTS.md` 작성 | 앞 단계 산출물을 바탕으로 오케스트레이터 초안을 작성한다. |
| 5 | 검증 | 파일 존재, 게이트 통과 여부, 문서 간 혼합 여부를 확인한다. |

## 단계 수 제한

| 항목 | 값 |
| --- | --- |
| 최소 단계 수 | 3개 |
| 최대 단계 수 | 5개 |

## 출력 파일

| 파일 | 역할 |
| --- | --- |
| `output/story-service.md` | 프로젝트 PRD에서 생성되는 서비스 유저스토리와 금지 조건 |
| `rounds/purpose.md` | 목적, 사용자, 완료 기준 |
| `rounds/pipeline.md` | 단계 분할, 입출력, 실패 시 복귀 |
| `rounds/artifacts.md` | 단계별 산출물 파일명과 재개 가능 여부 |
| `rounds/gates.md` | 기계가 셀 수 있는 통과 조건과 사람 승인 지점 |
| `rounds/roles.md` | 에이전트별 역할, 편집 폴더, 자연어 트리거 |
| `AGENTS.md` | 최종 오케스트레이터 초안 |

## 실패 시 복귀

| 실패 유형 | 복귀 지점 |
| --- | --- |
| 입력 누락 | R0 |
| 유저스토리 불일치 | R1 |
| 파이프라인 불일치 | R3 |
| 디자인 기준 위반 | `context/design.md` |
| 최종 검증 실패 | 직전 단계 |
