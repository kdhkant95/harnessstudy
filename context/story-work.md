# 디자인 워크플로우 유저스토리

이 문서는 서비스 기능 유저스토리인 `output/story-service.md`와 별개로, 디자이너가 Figma 파일에서 화면 설계를 진행할 때 따르는 작업 흐름을 정리한다.

| 순서 | 워크플로우 |
| --- | --- |
| 1 | [디자이너]가 [MUI 디자인 시스템]으로 [서비스 화면을 디자인한다] |
| 2 | [디자이너]가 [관련 레퍼런스]를 [조사하고 정리한다] |
| 3 | [디자이너]가 [레퍼런스 분석 내용]을 토대로 [서비스 화면 설계 문서를 구체화한다] |
| 4 | [디자이너]가 [Figma에 1440x1080 사이즈의 UI 키 스크린 2~3개]를 [그린다] |
| 5 | [디자이너와 내부 관계자]가 [작성된 화면 설계와 UI 키 스크린]을 [협의하고 개발 여부를 결정한다] |

## 디자인 기준

| 문서 | 용도 |
| --- | --- |
| `context/design.md` | 디자이너가 값을 따로 정하지 않아도 Figma 작업을 시작할 수 있는 디자인 기본값과 단계별 게이트 조건 |

디자인 기준과 게이트 조건은 이 워크플로우에만 적용하며, 서비스 기능 유저스토리인 `output/story-service.md`와 섞지 않는다.

## 워크플로우 문장 확인 규칙

사용자가 워크플로우 문장을 모두 말하면, 아래 세 가지를 추출해 표로 정리하고 사용자에게 맞는지 확인받는다.

| 추출 항목 | 용도 |
| --- | --- |
| 명사 | 산출물이 될 것 |
| 사용자가 멈칫했다고 표시한 지점 | 게이트가 될 것 |
| 다른 사람 또는 도구로 넘어가는 지점 | 에이전트 경계가 될 것 |

확인 전에는 추출 내용을 확정하거나 다른 문서와 섞지 않는다.
