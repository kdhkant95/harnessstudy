# 장기요양 도메인 지식

기준일: 2026-09-30

이 문서는 장기요양 관련 서비스를 기획·디자인할 때 참고하는 도메인 지식이다. 기능 요구사항을 새로 만드는 문서가 아니며, `input/PRD.md`, `brief.md`, `output/story-service.md`에 없는 기능을 이 문서만 근거로 추가하지 않는다.

## 적용 범위

| 항목 | 내용 |
| --- | --- |
| 도메인 | 대한민국 노인장기요양보험 및 장기요양기관 업무 |
| 사용 목적 | 서비스 기획, 화면 설계, 용어 정리, 게이트 조건 설계 |
| 우선순위 | 법령·공식 제도 설명 > 프로젝트 PRD/brief > 사용자 확인 |
| 금지 | 의학적 진단, 법률 자문, 급여비용 확정 산정, 권한 없는 정보 노출 |

## 핵심 정의

| 용어 | 정의 |
| --- | --- |
| 노인장기요양보험 | 고령 또는 노인성 질병 등으로 일상생활을 혼자 수행하기 어려운 사람에게 신체활동·가사활동 지원 등을 제공해 노후 생활 안정과 가족 부담 완화를 돕는 사회보험 제도 |
| 장기요양급여 | 6개월 이상 혼자 일상생활을 수행하기 어렵다고 인정된 사람에게 제공하는 신체활동·가사활동 지원, 간병 서비스 또는 이에 갈음하는 현금 등 |
| 수급자 | 장기요양인정을 받아 장기요양급여를 이용할 수 있는 사람 |
| 장기요양인정 | 국민건강보험공단의 조사와 등급판정 절차를 거쳐 장기요양급여 대상임을 인정받는 절차 |
| 장기요양등급 | 등급판정위원회가 심신 상태, 인정조사 결과, 의사소견서 등을 바탕으로 판정하는 등급 |
| 장기요양기관 | 수급자에게 재가급여 또는 시설급여 등을 제공하는 기관 |
| 장기요양인정서 | 인정 등급, 유효기간, 이용 가능한 급여 종류와 월 한도액 등을 확인하는 문서 |
| 표준장기요양이용계획서 | 장기요양 문제, 목표, 필요 영역, 필요 내용, 희망 급여, 유의사항, 이용계획과 비용 등을 담는 계획서 |

## 주요 사용자와 이해관계자

| 역할 | 도메인상 관심사 |
| --- | --- |
| 수급자 | 인정 등급, 이용 가능한 급여, 본인부담, 서비스 이용 일정 |
| 보호자·가족 | 급여계약, 비용, 서비스 이용 현황, 상태 변화 확인 |
| 장기요양기관 관리자 | 입소·퇴소, 급여계약, 인력·일정·청구, 권한 관리 |
| 요양보호사·간호 인력 | 서비스 제공 기록, 건강·상태 관찰, 일정 수행 |
| 시설장·최고관리자 | 기관 운영, 청구·수납·미수금, 위험·품질 관리 |
| 국민건강보험공단 | 인정조사, 등급판정 운영, 급여비용 심사·지급 |
| 등급판정위원회 | 장기요양인정 및 장기요양등급 판정 심의 |

## 인정과 이용 흐름

| 순서 | 단계 | 핵심 내용 | 화면 설계 시 주의 |
| --- | --- | --- | --- |
| 1 | 인정신청 | 65세 이상 또는 65세 미만 노인성 질병자가 신청 | 신청 여부와 인정 여부를 혼동하지 않는다 |
| 2 | 방문조사 | 공단 직원이 심신 상태와 희망 급여 등을 조사 | 조사 결과를 서비스 제공 기록처럼 표현하지 않는다 |
| 3 | 등급판정 | 등급판정위원회가 조사 결과와 의사소견서 등을 바탕으로 판정 | 앱 화면이 등급을 임의 판정하는 것처럼 보이면 안 된다 |
| 4 | 결과통지 | 장기요양인정서와 표준장기요양이용계획서 등을 통지 | 유효기간, 급여 종류, 월 한도액을 구분한다 |
| 5 | 급여계약 | 수급자와 장기요양기관이 급여 종류·내용·비용 등을 계약 | 계약 전 상태와 서비스 이용 중 상태를 구분한다 |
| 6 | 급여이용 | 인정서와 계획서 범위 안에서 급여를 이용 | 월 한도액 초과, 비급여, 본인부담을 혼동하지 않는다 |

## 급여 종류

| 대분류 | 세부 급여 | 설명 |
| --- | --- | --- |
| 재가급여 | 방문요양 | 수급자의 가정 등을 방문해 신체활동과 가사활동을 지원 |
| 재가급여 | 방문간호 | 간호사 등이 의사 등의 지시서에 따라 간호, 진료 보조, 요양 상담 등을 제공 |
| 재가급여 | 방문목욕 | 목욕 설비 차량 등을 이용해 방문 목욕을 제공 |
| 재가급여 | 주·야간보호 | 하루 중 일정 시간 장기요양기관에서 보호와 기능 유지·향상 활동을 제공 |
| 재가급여 | 단기보호 | 월 9일 이내 범위에서 장기요양기관에 보호하며 신체활동 지원 등을 제공 |
| 재가급여 | 복지용구 | 일상생활 또는 신체활동 지원에 필요한 용구를 제공하거나 대여 |
| 시설급여 | 노인의료복지시설 입소 | 요양병원을 제외한 노인의료복지시설에 장기간 입소해 신체활동 지원 등을 받음 |
| 특별현금급여 | 가족요양비 등 | 장기요양기관 이용이 어려운 예외적 경우 현금 급여를 지급 |

## 비용과 청구 개념

| 개념 | 설명 | 화면 설계 시 주의 |
| --- | --- | --- |
| 본인부담금 | 급여비용 중 수급자가 부담하는 금액 | 감경·면제 대상 여부를 확인 없이 단정하지 않는다 |
| 공단부담금 | 급여비용 중 공단이 심사 후 기관에 지급하는 금액 | 실제 지급액, 청구액, 수납액을 섞지 않는다 |
| 월 한도액 | 등급과 급여 종류 등에 따라 정해지는 이용 한도 | 초과분은 전액 본인부담이 될 수 있으므로 표시 기준을 명확히 한다 |
| 비급여 | 급여 범위 밖의 비용 | 급여비용과 한 카드 안에서 혼합하면 안 된다 |
| 급여비용 청구 | 기관이 재가급여 또는 시설급여 제공 후 공단에 비용을 청구하는 절차 | 청구 상태, 지급 상태, 실제 수납 상태를 구분한다 |

## 서비스 화면에서 자주 쓰는 업무 개념

| 개념 | 의미 | 설계 기준 |
| --- | --- | --- |
| 입소자 | 시설에 입소한 수급자 또는 관리 대상자 | 수급자, 보호자, 직원과 구분한다 |
| 생활실 | 입소자가 생활하는 공간 단위 | 방 번호·층 정보는 개인정보·권한 범위에 맞게 노출한다 |
| 외출·외박 | 입소자가 시설 밖에 있는 예정 또는 진행 상태 | 예정 시간과 실제 복귀 확인을 구분한다 |
| 복귀 확인 | 외출·외박 후 실제 돌아왔는지 확인하는 상태 | 예정 시간 도래만으로 복귀 완료로 표시하지 않는다 |
| 건강기록 | 활력, 체중, 식사, 배변, 투약 등 건강 관련 원기록 | 원기록 시각과 작성자를 보존한다 |
| 관찰 대상 | 최근 변화나 위험 신호가 있어 확인이 필요한 대상 | 관찰 분류는 진단이 아니라 운영 보조 정보다 |
| 평가·위험 현황 | 낙상, 욕창, 인지 등 평가별 위험 분류와 작성 상태 | 위험 결과와 평가 작성 상태를 분리한다 |
| 프로그램 기록 | 프로그램 종료 후 제공 내용과 참여 기록 | 종료 전 프로그램을 미작성으로 집계하지 않는다 |
| 상담 기록 | 상담 후 작성해야 하는 기록 | 상담 발생과 기록 작성 완료를 구분한다 |

## 권한과 정보 노출 원칙

| 원칙 | 기준 |
| --- | --- |
| 권한 우선 | Role과 원본 메뉴 권한이 볼 수 있는 데이터와 가능한 행동을 결정한다 |
| 조회 권한 없음 | 위젯, 행, 건수, AI 요약, 검색 결과, API 응답에서 해당 데이터를 노출하지 않는다 |
| 조회만 가능 | 상세보기만 제공하고 작성·수정·상태 변경 버튼은 제공하지 않는다 |
| 편집 가능 | 원본 기능 권한이 있을 때만 작성, 수정, 확인 중 변경, 조치 완료, 복귀 확인을 제공한다 |
| 복합 위젯 | 허용된 행만 표시하고 카운트·합계도 허용된 행 기준으로 계산한다 |
| 권한 없는 유형 | `0건`으로 표시하지 말고 위젯 또는 항목을 숨긴다 |
| 최고관리자 전용 | 경영·재무 데이터와 이를 포함한 AI 요약·추천은 최고관리자 외 사용자에게 노출하지 않는다 |

## 표현하면 안 되는 오해

| 오해 표현 | 올바른 표현 |
| --- | --- |
| 관찰 등급을 의학적 진단처럼 표현 | 운영 보조 정보, 확인 필요, 원기록 기준으로 표현 |
| 낙상 의심 알림을 실제 낙상 확정처럼 표현 | 현장 확인 전인 의심 알림으로 표현 |
| 출근 기록 없음을 결근으로 표현 | 기록 누락 또는 출근 기록 미확인으로 표현 |
| 감지 불가 기간을 정상 상태로 표현 | 장치 문제 또는 감지 불가 상태로 표현 |
| 실시간 연동이 아닌 데이터를 실시간이라고 표현 | 마지막 갱신 시각과 데이터 지연 상태를 표시 |
| 위험 인원을 평가 항목 간 합산해 전체 고위험 인원처럼 표현 | 평가별 위험 인원은 중복 가능하다고 분리 표시 |
| 청구 금액, 지급 금액, 실제 수납액, 미수금을 하나로 혼합 | 각 금액을 별도 지표로 표시 |

## 데이터와 시간 기준

| 항목 | 기준 |
| --- | --- |
| 기관 타임존 | 일정, 알림, 기록, 집계 기준은 기관 타임존을 사용한다 |
| 기준 시각 | 위젯과 집계에는 기준 시각을 함께 표시한다 |
| 마지막 갱신 시각 | 실시간이 아닌 데이터에는 마지막 갱신 시각을 표시한다 |
| 원기록 시각 | 건강기록, 알림, 조치 기록은 원기록 시각을 보존한다 |
| 유효기간 | 장기요양인정서, 급여계약, 평가·계획 갱신에는 유효기간을 별도 필드로 둔다 |

## 하네스 적용 규칙

| 규칙 | 적용 |
| --- | --- |
| 도메인 지식은 배경 기준이다 | 기능 요구사항은 `input/PRD.md`, `brief.md`, `output/story-service.md`에서 확인한다 |
| 도메인과 요구사항이 충돌하면 멈춘다 | 사용자에게 확인받기 전까지 임의 결정하지 않는다 |
| 도메인 용어는 일관되게 쓴다 | 수급자, 입소자, 보호자, 직원, 기관, 공단을 혼동하지 않는다 |
| 도메인 게이트를 만들 수 있다 | 권한, 최고관리자 전용, 진단 오해 방지, 시간 기준 위반은 게이트 후보가 된다 |
