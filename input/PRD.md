# 더비다 대시보드 PRD

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 초안 |
| 대상 | 더비다 웹 서비스 대시보드 |
| 기준 시안 | `vida-dashboard-all-widgets-preview.html` |
| 작성일 | 2026-09-29 |

## 1. 제품 개요

대시보드는 요양시설 구성원이 업무를 시작할 때, **지금 확인해야 할 사건과 오늘 처리해야 할 업무**를 빠르게 파악하고 원래 업무 화면으로 이동할 수 있게 하는 시작 화면이다.

단순 현황 집계가 아니라 다음 순서로 정보를 제시한다.

1. 긴급하거나 확인이 필요한 알림
2. 기한이 임박했거나 누락된 오늘의 업무와 일정
3. 지속 관찰이 필요한 입소자 변화와 위험 현황
4. 기관 운영 지표 및, 최고관리자에게만 제공되는 경영·재무 정보

대시보드는 원본 데이터를 편집하는 시스템이 아니다. 각 위젯은 해당 기능의 상태를 요약하고, 사용자를 원본 메뉴의 상세·작성 화면으로 연결한다. 단, 알림의 확인·조치와 같이 대시보드에서 직접 제공하는 상태 변경은 해당 원본 기능의 편집 권한을 따른다.

## 2. 목표와 비목표

### 목표

- 사용자가 로그인 후 30초 안에 우선 확인할 알림과 업무를 파악할 수 있다.
- 기한 지남, 기록 누락, 예정 일정, 건강 변화의 성격을 혼동하지 않게 구분한다.
- 기존 GNB 권한을 우회하지 않고, 권한 있는 데이터만 요약·집계·노출한다.
- 경영·재무 데이터는 최고관리자 Role에만 제공한다.
- 각 위젯에서 원본 화면으로 자연스럽게 이동할 수 있다.

### 비목표

- 대시보드에서 모든 기능을 완결하는 것
- 의학적 진단 또는 자동 처방 제공
- 알림만으로 실제 낙상·건강 이상을 확정하는 것
- 조회 권한이 없는 정보를 건수, AI 요약, 검색 결과를 통해 우회 노출하는 것
- 회계 결산, 급여 산정, 인사 승인을 대시보드에서 처리하는 것

## 3. 사용자와 Role

### 주요 사용자

| 사용자 | 대시보드에서 필요한 정보 |
| --- | --- |
| 시설장·최고관리자 | 기관 운영 전체, 경영·재무, 직원 현황, 주요 위험과 업무 |
| 관리자 | 담당 범위의 알림, 업무, 일정, 입소자 관찰 상태 |
| 간호·요양·사회복지 담당자 | 자신에게 허용된 건강·요양·프로그램·상담 관련 알림과 기록 업무 |
| 조회 전용 사용자 | 허용된 범위의 현황 및 상세보기 |

### 권한 원칙

1. Role은 **정보를 볼 수 있는 범위와 가능한 행동**을 결정한다.
2. 위젯 설정은 Role이 허용한 위젯 안에서의 개인 표시 선택이며, 권한을 부여하지 않는다.
3. 모든 위젯 데이터, 건수, 상세 진입, 다운로드·영상 등은 서버에서 원본 기능 권한을 검사한다.
4. 조회 권한이 없으면 위젯·행·건수·AI 요약에서 해당 데이터를 노출하지 않는다.
5. 조회만 가능하면 상세보기만 제공하며 작성·수정·상태 변경 버튼은 제공하지 않는다.
6. 조회와 편집이 가능할 때만 작성, 수정, 확인 중 변경, 조치 완료, 복귀 확인을 제공한다.

### 경영·재무 권한 정책 — 확정

| 항목 | 정책 |
| --- | --- |
| 경영 요약·제안 | 최고관리자 Role만 조회 |
| 수입·지출, 미수금, 장기요양급여 청구 정보 | 최고관리자 Role만 조회 |
| 재무 내용을 포함하는 AI 요약·추천 | 최고관리자 Role만 조회 |
| 최고관리자 외 사용자 | 위젯, 위젯 설정 목록, 알림·업무·AI 문구에서 재무 정보를 모두 제외 |

직원·근무 현황과 AI 사용 현황의 Role 범위는 별도 정책으로 확정한다. 현재 시안에서는 관리자 전용 보조 정보로 취급한다.

## 4. 정보 구조와 기본 배치

데스크톱은 12열 그리드를 기준으로 하며, 화면은 다음 순서로 구성한다.

| 순서 | 영역 | 위젯 | 권장 폭 |
| --- | --- | --- |
| 1 | 오늘의 대응 | 확인이 필요한 알림 | 12열 |
| 2 | 오늘의 대응 | 오늘 처리할 업무 / 오늘의 일정 | 7열 / 5열 |
| 3 | 입소자 케어 | 건강 변화·관찰 대상 / 평가·위험 현황 | 8열 / 4열 |
| 4 | 입소자 케어 | 입소자 현황 | 12열 |
| 5 | 시설·경영 | 경영 요약·제안 / 수입·지출 / 직원·근무 현황 | 각 4열 |
| 6 | 시설·경영 | 프로그램·상담 기록 / 시설 일정·점검 / AI 사용 현황 | 각 4열 |

- 권한상 표시할 수 없는 위젯은 숨기고 남은 위젯을 재배치한다. 빈 카드나 잠금 카드로 공간을 유지하지 않는다.
- 모바일에서는 위젯을 단일 열로 쌓되, 우선순위는 데스크톱과 동일하게 유지한다.
- 위젯 내부 스크롤은 지양한다. 미리보기 목록은 4~6개로 제한하고, 나머지는 전체보기에서 제공한다.

## 5. 공통 위젯 규칙

### 공통 구조

| 영역 | 구성 |
| --- | --- |
| 헤더 | 위젯 제목, 짧은 설명 또는 기준 시각, 전체보기 |
| 본문 | 핵심 수치 또는 우선순위 목록 |
| 하단 | 집계 기준, 데이터 수집 시각, 제한 사항 등 필요한 보조 정보 |

### 공통 상태

| 상태 | 화면 규칙 |
| --- | --- |
| 정상 | 최신 데이터와 행동 제공 |
| 데이터 0건 | 예: `오늘 예정된 일정이 없습니다.` 처럼 해당 범위를 명시 |
| 로딩 | 위젯 형태에 맞는 스켈레톤 |
| 조회 실패 | `정보를 불러오지 못했습니다.`와 재시도 제공 |
| 데이터 지연 | 마지막 수집·갱신 시각과 지연 상태 표시 |
| 조회 전용 | 상세보기는 제공하고 편집 행동 제거 |
| 부분 권한 | 허용된 항목만 표시하고, 건수도 같은 범위에서 집계 |
| 권한 없음 | 위젯 자체와 위젯 설정 항목을 숨김 |

### 상태 표현

- 상태는 색상만으로 표현하지 않는다. 상태명을 반드시 함께 표기한다.
- 긴급·미확인·기한 지남에는 주의 색상을 사용하되, 같은 색상이라도 의미가 다른 경우 텍스트와 아이콘을 함께 사용한다.
- `미확인`, `확인 중`, `조치 완료`는 명확히 분리한다. 알림 확인은 해결을 의미하지 않는다.

## 6. 위젯 상세 요구사항

### 6.1 확인이 필요한 알림

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 안전·건강·장치 관련 사건을 빠르게 확인하고 조치를 시작한다. |
| 원본 권한 | 알림 유형별 원본 메뉴 권한. 낙상·ROI는 낙상감지, 활력 기준 이탈은 건강기록 권한을 따른다. |
| 최소 정보 | 유형, 대상 또는 장소, 생활실·카메라, 발생 시각, 감지 내용, 상태 |
| 우선순위 | 미확인 → 확인 중 순으로 정렬하며, 같은 상태에서는 최신 발생 순으로 정렬 |
| 직접 행동 | 편집 권한이 있을 때 `확인 중으로 변경`, 결과·조치 내용 입력 후 `조치 완료` |
| 상세 이동 | 알림 원본, 관련 입소자 기록, 낙상 영상 또는 CCTV 상태 |

알림 유형은 적어도 아래를 구분한다.

- 낙상 의심: 실제 낙상 여부를 확정하지 않으며, 현장 확인 전임을 명시한다.
- 관찰 구역(ROI) 이탈: 카메라, 구역 이름, 이탈 시각을 제공한다.
- 활력·건강 기준 이탈: 실제 측정값, 단위, 측정 시각, 적용된 기관 기준을 원기록에서 확인할 수 있게 한다.
- 장치 문제: CCTV 연결 끊김 등은 입소자 이상 알림과 별도의 장치 상태로 표시한다. 감지 불가 기간을 정상 상태로 표현하지 않는다.

완료된 알림은 기본 위젯 목록에서 제거하고, 알림 이력에서는 결과·조치 내용과 함께 조회할 수 있어야 한다.

### 6.2 오늘 처리할 업무

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 누락되었거나 기한이 임박한 기록·평가·갱신 업무를 제시한다. |
| 원본 권한 | 업무를 생성한 원본 메뉴의 조회·편집 권한 |
| 필터 | 전체 / 기한 지남 / 오늘 |
| 정렬 | 기한 지남 → 오늘 마감 → 오늘 확인 필요 → 이후 예정 |
| 최소 정보 | 업무명, 대상, 발생·기한 근거, 상태, 대상 수, 원본 화면 행동 |

업무 후보:

- 측정 주기 초과
- 정기 평가·재평가 기한 초과
- 장기요양 인정 유효기간 확인
- 급여제공계획 갱신
- 종료된 프로그램의 제공 기록 미작성·작성 중
- 상담 후 기록 미작성

집계 기준은 기관 설정과 입소자별 주기에 따라 산정한다. 주기를 모르는 상태에서 임의의 마감일을 생성하지 않는다.

### 6.3 오늘의 일정

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 오늘의 예정·진행·복귀 확인이 필요한 일정을 시간순으로 확인한다. |
| 원본 권한 | 병원·면회·외출/외박·프로그램·시설 일정 각각의 원본 조회 권한 |
| 표시 방식 | 선택한 날짜와 시간순 목록을 기본으로 하며, 주간 날짜 스트립과 전체 캘린더 진입 제공 |
| 최소 정보 | 시각, 일정명, 대상 또는 장소, 상태 |
| 주요 행동 | 일정 상세, 전체 캘린더, 일정 등록(편집 권한 필요) |

일정 유형은 병원 진료, 보호자 면회, 외출·외박, 복귀 예정, 프로그램, 시설 행사·점검을 포함한다. 외출·외박은 예정 시간만이 아니라 실제 복귀 확인 상태를 관리한다.

외부 캘린더를 사용 중인 경우, 더비다와 외부 캘린더 중 어떤 시스템을 일정 원본으로 둘지 별도 결정한다. 동기화 전에는 같은 일정을 두 번 입력하게 만들지 않는다.

### 6.4 건강 변화·관찰 대상

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 단순 관찰 등급이 아니라 최근 변화와 확인 근거를 제시한다. |
| 원본 권한 | 건강기록 조회 권한 |
| 최소 정보 | 입소자명, 생활실, 관찰 분류, 구체적 사유, 최근 값·단위·시각, 추이 |
| 상세 행동 | 입소자 건강 기록 상세 및 원기록으로 이동 |

예시 표현:

- `체중 변화 확인 필요 · 58.2 → 56.8kg`
- `혈압 기준 이탈 · 162 / 96mmHg · 오늘 09:40`
- `식사 섭취 기록 감소 · 최근 3회 절반 이하`

추이 그래프는 기간·단위를 제공한다. 서로 다른 지표의 기울기를 동일 선상에서 비교하도록 만들지 않으며, 정성 기록은 억지로 수치 그래프로 변환하지 않는다. 관찰 분류는 운영 보조 정보이며 진단을 의미하지 않는다.

### 6.5 평가·위험 현황

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 평가별 최근 위험 분류와 평가 누락·기한 초과를 함께 확인한다. |
| 원본 권한 | 평가 기능이 속한 메뉴의 조회·편집 권한 |
| 최소 정보 | 평가 항목, 위험 분류 인원, 평가 완료 인원, 미평가 인원, 기한 초과 인원 |
| 행동 | 대상 보기, 평가 작성 |

고위험 인원은 평가 항목 간 중복될 수 있다. 따라서 평가별 고위험 인원을 합산해 전체 고위험 입소자 수로 표시하지 않는다. 위험 결과와 평가 작성 상태는 분리해 표현한다.

### 6.6 입소자 현황

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 시설 수용과 이번 주 입·퇴소, 외출·외박 상태를 보조 지표로 제공한다. |
| 원본 권한 | 입소자 조회 권한 |
| 최소 정보 | 현재 입소자 / 정원, 공실, 외출 중, 외박 중, 입소 예정, 퇴소 예정 |
| 행동 | 해당 조건이 적용된 입소자 목록으로 이동 |

대형 도넛 차트보다 공간을 적게 쓰는 수치·진행 막대형 요약을 사용한다. 입소율은 `현재 입소자 ÷ 정원`으로 산정하며 수치와 비율이 일치해야 한다.

### 6.7 프로그램·상담 기록

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 종료 후 작성해야 할 프로그램 제공 기록과 상담 기록을 확인한다. |
| 원본 권한 | 프로그램 기록·상담 기록 각각의 조회·편집 권한 |
| 최소 정보 | 종료된 프로그램 수, 기록 완료·미작성·작성 중 상태, 기록 대상 |
| 행동 | 기록 작성, 이어 쓰기, 기록 보기 |

작성률의 분모에는 **종료된 프로그램만** 포함한다. 아직 진행 예정인 프로그램은 미작성으로 집계하지 않는다. 상단 `오늘 처리할 업무`와 동일한 원본 상태를 공유해야 한다.

### 6.8 시설 일정·점검

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 다가오는 시설 행사·점검과 결과 미작성 건을 확인한다. |
| 원본 권한 | 정기점검 또는 관련 시설 일정 권한 |
| 최소 정보 | 날짜, 일정·점검명, 장소 또는 담당자, 상태, 결과 작성 필요 여부 |
| 행동 | 상세보기, 점검 결과 작성 |

회의·교육·정기점검이 통합된 GNB를 도입하더라도 원본 기능과 권한은 각각 유지한다. GNB의 통합은 탐색 구조를 위한 것이며 권한을 하나로 합치는 근거가 아니다.

### 6.9 직원·근무 현황

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 당일 근무 예정과 기록 확인이 필요한 인원을 보조적으로 제시한다. |
| 원본 권한 | 직원관리·근무관리 권한 범위 확정 필요 |
| 최소 정보 | 근무 예정, 출근 기록, 기록 미확인, 연차 승인 대기, 필수 교육 미이수 |
| 행동 | 근무표, 출퇴근 기록, 휴가·교육 관련 원본 화면 |

`출근 기록 없음`은 `결근`과 동일하지 않다. 기록이 누락된 상태로만 표현하고, 승인·근무표·출퇴근 원기록을 확인할 수 있게 한다.

### 6.10 AI 사용 현황

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 기관 내 AI 기능의 사용량을 보조적으로 파악한다. |
| 원본 권한 | AI 사용·요금 관리 권한 범위 확정 필요 |
| 최소 정보 | 집계 기간, 기능별 사용 횟수, 집계된 토큰, 집계 제외 기준 |
| 행동 | 전체 사용 내역 |

AI 사용량과 비용은 분리한다. 비용·요금은 경영·재무 성격이므로 최고관리자 전용이다. 이 위젯은 대시보드 하단에 배치한다.

### 6.11 경영 요약·제안 — 최고관리자 전용

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 운영상 확인할 주요 사항과 실행 가능한 후속 업무를 요약한다. |
| 권한 | 최고관리자 Role |
| 최소 정보 | 제안 내용, 근거 요약, 기준 시각, 관련 업무 진입 |
| 행동 | 근거 확인, 대상 목록, 관련 원본 화면 이동 |

AI가 생성한 문구는 `AI 초안`으로 표시하고, 원자료·기준 시각을 확인할 수 있어야 한다. 재무 정보가 포함된 제안은 최고관리자 외 사용자에게는 생성·집계·노출하지 않는다.

### 6.12 수입·지출 — 최고관리자 전용

| 항목 | 요구사항 |
| --- | --- |
| 목적 | 수입·지출·차액과 수납·청구 관련 상태를 한눈에 파악한다. |
| 권한 | 최고관리자 Role |
| 최소 정보 | 기간, 수납 수입, 지출, 차액, 미수금, 장기요양급여 청구 상태 |
| 행동 | 수납·지출·청구 상세 보기 |

진행 중인 이번 달은 전월 전체가 아닌 **같은 일자 범위**와 비교한다. 청구 금액, 지급 금액, 실제 수납액, 미수금은 서로 다른 값으로 관리하며 하나의 금액으로 혼합하지 않는다. 표시 금액이 회계 결산과 다를 수 있다면 집계 기준을 명시한다.

| 위젯 | 표시 조건 | 조회만 가능 | 편집 가능 |
| --- | --- | --- | --- |

| 경영 요약·제안 | 최고관리자 | 해당 없음 | 연결된 원본 권한에 따라 별도 적용 |

복합 위젯에서 일부 데이터 권한만 있는 경우:

- 허용된 행만 표시한다.
- 카운트·합계도 허용된 행으로만 계산한다.
- 권한이 없는 유형을 `0건`으로 표시하지 않는다.
- 표시 가능한 행이 하나도 없으면 위젯을 숨긴다.

## 8. 데이터와 집계 기준

| 데이터 | 기준 |
| --- | --- |
| 알림 | 상태가 미확인 또는 확인 중인 허용 범위의 알림. 완료는 이력에서 조회 |
| 업무 | 기관 설정·입소자별 주기·기한을 충족하지 못한 원본 업무 |
| 일정 | 선택 날짜에 속하는 허용 범위의 일정. 시간대 기준은 기관 타임존 |
| 건강 관찰 | 최근 측정·기록과 정의된 관찰 규칙. 원기록 시각 노출 |
| 평가 위험 | 각 평가의 최신 유효 결과와 독립적인 완료·미평가 상태 |
| 입소자 현황 | 현재 유효한 입소·외출·외박·입퇴소 예정 상태 |
| 프로그램 기록 | 종료된 프로그램의 제공 기록 상태 |
| 재무 | 명시된 기준일과 동기간 비교. 수입·지출·청구·수납을 분리 |

모든 위젯은 기관 타임존, 기준 시각, 데이터 마지막 갱신 시각을 일관되게 사용한다. 실시간 연동이 아닌 데이터는 ‘실시간’으로 표현하지 않는다.

## 9. 사용자 흐름

### 알림 처리

1. 사용자가 미확인 알림을 선택한다.
2. 대상, 시각, 감지 내용, 원기록·영상·장치 상태를 확인한다.
3. 편집 권한이 있으면 `확인 중`으로 변경한다.
4. 현장 확인 뒤 결과와 조치 내용을 입력한다.
5. 조치 완료 후 기본 알림 목록에서는 제외하고 알림 이력에 보존한다.

### 업무 처리

1. 사용자가 기한 지남 또는 오늘 필터를 선택한다.
2. 대상과 기한 근거를 확인한다.
3. 원본 작성·수정 화면으로 이동한다.
4. 원본 상태가 변경되면 업무 위젯과 관련 위젯의 집계가 갱신된다.

### 일정 확인

1. 사용자가 날짜를 선택한다.
2. 선택 날짜의 시간순 일정과 상태를 확인한다.
3. 일정 상세 또는 캘린더로 이동한다.
4. 외출·외박은 실제 복귀 여부가 갱신되면 상태를 갱신한다.

## 10. 기능 요구사항

### 필수 기능

- [ ] 로그인한 사용자의 Role 및 메뉴별 조회·편집 권한을 반영한다.
- [ ] 권한 없는 데이터가 API 응답, 위젯, 건수, AI 요약에 포함되지 않는다.
- [ ] 위젯별 전체보기와 원본 상세 화면 이동을 제공한다.
- [ ] 오늘 처리할 업무의 필터와 정렬을 제공한다.
- [ ] 오늘의 일정에서 날짜 선택과 전체 캘린더 진입을 제공한다.
- [ ] 알림 상태를 미확인 / 확인 중 / 조치 완료로 관리한다.
- [ ] 완료된 알림은 조치 결과·내용과 함께 이력으로 보존한다.
- [ ] 위젯 설정은 조회 가능한 위젯만 대상으로 표시 여부를 저장한다.
- [ ] 최고관리자 외 사용자에게 경영·재무 위젯 및 해당 데이터가 노출되지 않는다.
- [ ] 로딩, 빈 상태, 오류, 데이터 지연 상태를 위젯별로 제공한다.

### 비기능 요구사항

- [ ] 데스크톱 12열 및 모바일 단일 열에서 가로 스크롤 없이 표시한다.
- [ ] 키보드로 버튼·필터·상세 진입을 조작할 수 있다.
- [ ] 상태는 색상 외 텍스트와 아이콘으로도 구분한다.
- [ ] 집계 기준·기준 시각·마지막 갱신 시각을 필요한 위젯에 제공한다.
- [ ] 사용자별 위젯 설정은 권한 변경·기관 변경 시 재검증한다.
- [ ] 권한 검사는 클라이언트 화면 숨김에만 의존하지 않고 서버 요청마다 수행한다.

## 11. 수용 기준

### 권한

- [ ] 최고관리자가 아닌 사용자가 로그인하면 경영 요약·제안과 수입·지출 위젯이 보이지 않는다.
- [ ] 같은 사용자의 위젯 설정 팝업에도 위 두 위젯이 표시되지 않는다.
- [ ] 최고관리자가 아닌 사용자의 알림 건수·업무·AI 요약에 미수금, 수입·지출, 청구 금액이 포함되지 않는다.
- [ ] 건강기록 조회만 있고 낙상감지 조회가 없는 사용자는 건강 관련 알림만 본다.
- [ ] 조회 전용 사용자는 조치 완료, 기록 작성, 일정 등록 등 변경 행동을 실행할 수 없다.
- [ ] URL·API를 직접 요청하더라도 권한 없는 원본 데이터가 반환되지 않는다.

### 알림·업무·일정

- [ ] 알림을 `확인 중`으로 바꿔도 조치 완료 전까지 기본 목록에 남는다.
- [ ] 조치 완료에는 결과와 조치 내용 입력이 필요하다.
- [ ] 조치 완료 알림은 기본 목록에서 사라지고 알림 이력에는 남는다.
- [ ] 기한 지남 필터는 기한이 지난 업무만, 오늘 필터는 오늘 처리 대상만 표시한다.
- [ ] 일정 날짜를 바꾸면 해당 날짜 일정만 표시된다.
- [ ] 외출·외박 복귀 예정은 복귀 확인 상태를 표시한다.

### 지표

- [ ] 입소율 수치와 현재 입소자·정원 값이 수학적으로 일치한다.
- [ ] 평가별 위험 인원이 중복 합산되지 않는다.
- [ ] 프로그램 기록 작성률은 종료된 프로그램만 분모로 사용한다.
- [ ] `출근 기록 없음`은 결근으로 표현되지 않는다.
- [ ] 재무 비교는 같은 일자 범위로 계산된다.
